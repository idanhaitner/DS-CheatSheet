4.1 Binary Heap (Priority Queue)

About the heap

A complete binary tree in an array. Max-heap: parent ≥ children. Root = max. Height \(\Theta(\log n)\).

Index math (0-based) 
parent(i) = (i - 1) / 2
left(i)   = 2*i + 1

Why BuildHeap is Θ(n) — the proof (know it cold)

BuildMaxHeap runs MaxHeapify from the last internal node (index \(\lfloor n/2\rfloor - 1\)) down to the root — leaves are already heaps. Naive count: \(n/2\) calls × \(O(\log n)\) = \(O(n\log n)\), but that's loose:

  • MaxHeapify on a node of height \(h\) costs \(O(h)\), and there are at most \(\lceil n/2^{h+1}\rceil\) nodes of height \(h\).
  • Total: \(\sum_{h} \frac{n}{2^{h+1}}\cdot O(h) = O\big(n\sum_{h=0}^{\infty} \frac{h}{2^h}\big) = O(2n) = O(n)\), using \(\sum h/2^h = 2\).
2026A trap — heap ≠ sorted: BuildMinHeap only guarantees parent ≤ children, not a sorted array. Even with many duplicates it can output e.g. \([1,3,2,3,3,2,3]\) (valid min-heap, not sorted). Answers of the form "always sorted" are wrong; "sometimes" needs one counterexample + one positive example.
Structural quiz facts: in a max-heap with distinct keys, the largest is at \(A[0]\), the 2nd largest is a child of the root, but the 3rd largest can sit at depth 1 or 2 (any of up to 6 cells for \(n=10\)). IncreaseKey rejects a key smaller than the current one; Insert = append \(-\infty\), then IncreaseKey.

4.2 Huffman Coding

Optimal prefix-free code for data compression: frequent characters get shorter codes. Build a binary tree bottom-up with a min-heap.

  1. Make a leaf for each character with its frequency; put all in a min-heap.
  2. Repeatedly extractMin the two smallest, create a parent with their summed frequency, insert it back.
  3. Repeat until one tree remains. Left edge = 0, right edge = 1; a character's code = path from root.
PhaseTimeWhy
Build tree (n distinct symbols)O(n log n)n−1 merges; each merge = 2 extractMin + 1 insert on a min-heap of size O(n)
Build code tableO(n)One DFS/BFS from root to label each leaf with its 0/1 path
Encode message (length N)O(N)Look up each character's code in O(1) (hash table / array)
Decode messageO(N)Walk the tree one bit at a time; each source symbol read once
SpaceO(n)Tree has 2n−1 nodes; code table has n entries

Cost of a code: \(\mathrm{cost}(T)=\sum_c freq(c)\cdot depth(c)\) = total encoded bits; Huffman minimizes this among all prefix codes. An optimal prefix code is not unique (ties break both ways). An optimal tree is always full (every internal node has 2 children).

Optimality proof (lecture 11 — never asked yet, prime Moed B material)

Sibling lemma (exchange argument): there exists an optimal prefix tree in which the two least-frequent symbols \(x,y\) are siblings at the deepest level. Proof: take any optimal tree; a deepest leaf must have a sibling leaf (else delete the unary node — cheaper, contradiction). Swap \(x,y\) with those two deepest sibling leaves: each swap moves a rarer symbol deeper and a more frequent one shallower, so the cost does not increase. ∎

Theorem (Huffman is optimal), induction on alphabet size \(|C|\):

  1. Let \(T\) = Huffman's tree, \(S\) = an optimal tree with \(x,y\) siblings (exists by the lemma).
  2. Contract \(x,y\) into one symbol \(z\) with \(z.freq = x.freq + y.freq\), giving trees \(T', S'\) over the smaller alphabet \(C'\).
  3. \(\mathrm{cost}(T) = \mathrm{cost}(T') + z.freq\) and \(\mathrm{cost}(S) = \mathrm{cost}(S') + z.freq\) (removing the two leaves saves exactly one bit per occurrence of \(x\) or \(y\)).
  4. \(T'\) is a Huffman tree on \(C'\), optimal by induction ⟹ \(\mathrm{cost}(T')\le \mathrm{cost}(S')\) ⟹ \(\mathrm{cost}(T)\le \mathrm{cost}(S)\). ∎

Min / max total bits (2026A Q2c pattern)

Question type: "over all strings of length \(n\) with constraints, what is the minimum/maximum number of bits Huffman produces?"

  • Minimize ⟹ make the distribution as skewed as possible: one symbol dominates and gets a length-1 code. Example over \(\{a,b,c,d\}\), each appearing ≥ once: \(a^{n-3}bcd\) → lengths 1,2,3,3 → total \((n-3)+2+3+3 = n+5\) bits.
  • Maximize / balanced ⟹ equal frequencies \(n/4\) each → all codes length 2 → \(2n\) bits. Balanced = worst for compression, not best!

The input \(C\) is a list of characters and their frequencies.

pseudocode 
Huffman(C):
    n = |C|
    Q = priority queue of C
    for i = 1 to n - 1:
        allocate a new node z
        z.left = ExtractMin(Q)
        z.right = ExtractMin(Q)
        z.freq = z.left.freq + z.right.freq
        Insert(Q, z)
    return ExtractMin(Q)

4.3 Lempel-Ziv Compression

Unlike Huffman (which needs frequencies in advance), Lempel-Ziv is a dictionary-based method that learns repeated substrings on the fly, replacing repeats with short references. Behind gzip, ZIP, PNG.

  • Maintain a growing dictionary of substrings seen so far.
  • Find the longest prefix already in the dictionary; output its index, then add (prefix + next char) as a new entry.
  • Later repetitions become a single compact index instead of raw characters.

Example: encode A B A B A B A

StepOutput tokenNew dictionary entry
read A (new)(0, A)1 = "A"
read B (new)(0, B)2 = "B"
read AB (A known)(1, B)3 = "AB"
read ABA (AB known)(3, A)4 = "ABA"

Time complexity

PhaseTimeWhy
Encode (naive dictionary scan)O(N²)≤ N steps; each step may scan all O(N) dictionary entries and compare prefixes
Encode (with trie / efficient match)O(N)One left-to-right pass; trie lookup per step is O(match length), totals O(N)
DecodeO(N)One pass; each token outputs ≥ 1 new character and adds one dictionary entry
SpaceO(N)Dictionary grows to O(N) phrases in the worst case

LZ78 phrase-count bounds (2026A Q2d pattern)

Lecture definition: each block = the longest prefix of the remaining text that equals a previous block, plus one character; block \(i\) is encoded as a pair \((j, c)\) = (index of parent block, last char), costing \(\approx\log_2 n\) bits. So total bits = (#phrases) · log n, and min/max questions reduce to counting phrases \(p\):

  • Key bound: the \(i\)-th new phrase has length at most \(i\) (previous block + 1 char, and blocks grow by at most one char at a time). Hence \(n \le 1+2+\cdots+p = \frac{p(p+1)}{2}\) ⟹ \(p = \Omega(\sqrt n)\), i.e. you can never do better than \(\Theta(\sqrt n)\) phrases.
  • Tight: phrases of lengths \(1,2,\ldots,p\) (e.g. \(a\,|\,ab\,|\,abc\,|\,abcd\,|\,abcda\,|\,\ldots\)) achieve it ⟹ minimum total bits \(=\Theta(\sqrt n \log n)\). Not \(\Theta(\log n)\) — phrase lengths grow by +1 per step, not exponentially.
Encode time (lecture): trie with linked-list children \(\Theta(\sigma n)\); with hashed children (or one global hash on pairs \((j,c)\)) expected \(\Theta(n)\). Decode rebuilds the trie with parent pointers in \(\Theta(n)\).
Huffman vs Lempel-Ziv:
  • Huffman: statistical, per-symbol, needs frequencies, optimal prefix code for a known distribution. Build: O(n log n).
  • Lempel-Ziv: dictionary, exploits repeated substrings, adaptive/online (one pass), decoder rebuilds the same dictionary. Encode: O(N²) naive / O(N) with trie; decode: O(N).
Both are lossless. Real tools (DEFLATE in gzip/PNG) combine LZ + Huffman.
